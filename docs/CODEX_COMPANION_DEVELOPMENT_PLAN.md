# Codex Companion 开发计划

> 基于 `CODEX_COMPANION_DESIGN.md` 的可交付计划。

## 1. 开发顺序

先验证 Codex app-server 能稳定返回结构化限额，再做原生菜单栏和推荐逻辑。不依赖网页抓取，也不从日志推断额度。

| 阶段 | 目标 | 预计工作量 | 完成标志 |
|---|---|---:|---|
| 0. 技术验证 | app-server 读取可用 | 1 天 | 读取真实短/长周期与重置时间 |
| 1. 最小闭环 | 扩展到菜单栏 | 2–3 天 | 两账号可同步并正确推荐 |
| 2. 日常可用 | 可靠性与提醒 | 2–3 天 | 可连续使用 7 天 |
| 3. 发布准备 | 安装、隐私、回归 | 1–2 天 | 可由非开发者独立安装验证 |

## 2. 阶段 0：技术验证

### 交付物

- app-server 只读客户端。
- 一个只输出脱敏限额快照的解码器。
- 协议 fixture 和人工验证记录。

### 工作项

1. 使用 `initialize` 与 `account/rateLimits/read` 验证真实 Profile。
2. 解码 `usedPercent`、`windowDurationMins` 和 `resetsAt`。
3. 验证超时、中断和无登录 Profile 的失败行为。
4. 收集正常、达到限制、窗口缺失等 fixture。
5. 以窗口分钟数映射短/长周期，未知窗口保留原始分钟数。

### 验收

- 正常 Profile 的短/长窗口与 Codex CLI 返回值一致。
- 无法读取时明确报错，不生成虚假额度。
- 快照和日志不含会话内容、Cookie、Authorization 或邮箱。

### 决策门

若 app-server 不返回限额，应用保持上次快照并提示升级/检查 Codex CLI；不使用私有网页接口补救。

## 3. 阶段 1：最小闭环

### 交付物

- Swift/SwiftUI 菜单栏应用。
- app-server 进程客户端。
- JSON 本地快照持久层。
- 双账号设置页和账号建议。

### 工作项

1. 建立结构化响应解码、输入验证与版本兼容检查。
2. 创建账号、快照持久化；写入时以账号覆盖最新快照。
3. 将每次查询固定限制为只读 RPC 方法，并限制进程超时。
4. 实现菜单栏摘要、倒计时和“数据过期”状态。
5. 按 70/30 规则实现推荐和解释文本。
6. 实现“打开配置文件”和“立即刷新”操作。

### 验收场景

| 场景 | 预期 |
|---|---|
| Profile A 上报 42% / 73% | 只更新账号 A |
| Profile B 上报 81% / 91% | 推荐账号 B，列出分差 |
| 15 分钟无新数据 | 显示数据过期，不继续推荐 |
| 主程序重启 | 保留最后快照和同步时间 |
| 同一事件上报两次 | 只保留一个历史快照 |
| 页面无法解析 | 保留旧快照，显示同步失败原因 |

## 4. 阶段 2：日常可用

### 工作项

- 30 天历史图与原始快照查看。
- 通知去重：低额度、即将重置、建议变更。
- JSON 导入导出、90 天自动清理和一键清除。
- Launch at Login、错误日志导出、解析器自检页。
- 使用 Chrome、Arc、Brave 各完成一次验证。

### 稳定性验收

- 连续运行 7 天，内存无持续增长趋势。
- 通知不重复轰炸；同一状态每个周期只发一次。
- 离线或浏览器关闭时，UI 保留最后数据并提示陈旧状态。
- 从备份恢复后，账号、快照和建议结果一致。

## 5. 阶段 3：发布准备

### 文档与安装

- README：用途、支持范围、限制、安装、首次绑定、故障排查。
- PRIVACY：采集字段、明确不采集字段、存储位置、删除方法。
- TEST_PLAN：自动测试与人工验收清单。
- 签名与打包说明；首次版本可先采用开发者手动安装流程，公证签名独立排期。

### 发布门槛

- 无高危权限与无明文凭证。
- 所有核心逻辑单测通过：解析映射、过期判断、推荐算法、通知去重。
- 两个实际账号 Profile 连续三天各成功同步至少一次。
- 在 README 中明确“以官方 Usage Dashboard 为准”。

## 6. 技术拆分

```text
codex-companion/
├── apps/
│   ├── macos/                 # Swift/SwiftUI/MenuBarExtra
│   └── browser-extension/     # WXT + TypeScript + MV3
├── packages/
│   └── protocol/              # JSON schema 与测试 fixture
├── docs/
│   ├── CODEX_COMPANION_DESIGN.md
│   ├── CODEX_COMPANION_DEVELOPMENT_PLAN.md
│   ├── PRIVACY.md
│   └── TEST_PLAN.md
└── scripts/
    ├── install-native-host.sh
    └── package-extension.sh
```

建议实现顺序：`protocol` → `browser-extension parser` → `native host` → `SQLite` → `menu bar` → `recommendation` → `notifications`。

## 7. 测试策略

- **单元测试**：百分比、时间解析、时区转换、快照去重、评分规则、过期判定、通知幂等。
- **Fixture 测试**：正常、只显示一种窗口、文案变更、加载中、达到限制、页面错误。
- **集成测试**：扩展 → Native Host → SQLite → 菜单栏 ViewModel。
- **人工测试**：两个浏览器 Profile、网络断开、应用重启、浏览器重启、跨午夜和跨周重置。
- **隐私检查**：检查 SQLite、扩展存储和日志，确认不出现 Cookie、Bearer、聊天文本、完整 URL 查询参数。

## 8. 风险登记与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Usage 页面改版 | 解析失效 | 独立解析器、fixture 回归、失败不覆盖旧数据 |
| 额度窗口改名或调整 | 推荐错误 | 保存原标签；未知窗口不强行映射；配置化映射 |
| 页面只在用户打开时更新 | 数据陈旧 | 明显显示同步时间；不伪造实时性 |
| 多账号误绑定 | 错误建议 | Profile 首次绑定确认、设置页可重新绑定 |
| 重置时间含糊或本地化 | 倒计时错误 | 同时保存原文与已解析时间；无法解析时只显示原文 |
| 把日志活动当额度 | 用户误判 | v0.1 不接 CLI；未来界面严格区隔“官方额度”和“本地活动” |

## 9. 首个开发 Sprint 的完成定义

Sprint 只覆盖阶段 0 与阶段 1：

- 扩展能把两个 Profile 的已展示 Usage 数据送入本地应用。
- 菜单栏能展示短周期、长周期、两个重置倒计时、同步时间和推荐账号。
- 数据无效或陈旧时，不给出误导性推荐。
- 包含基本测试、安装步骤和隐私说明草案。

之后才启动历史、通知、CLI 活动统计或多工具支持。
